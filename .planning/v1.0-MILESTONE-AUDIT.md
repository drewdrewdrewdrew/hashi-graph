## Tech Debt (Non-Critical)

### Phase 02-bptt-training-loop

**1. Latent `UnboundLocalError` for non-`diff-cont` modes with BPTT enabled**
- `scales` is only assigned in the `if mode == "diff-cont":` branch (lines 358–373). If `bptt.enabled: true` and mode is `flow-blind` or `diff-discrete`, line 545 (`scales=scales`) raises `UnboundLocalError`.
- **Current exposure:** None — YAML sets `mode: diff-cont`.
- **Impact if triggered:** Runtime crash on first BPTT-enabled training run with a different mode.
- **Fix:** Initialize `scales = None` before the mode branch, or add an explicit guard in `_run_bptt_window` call.

**2. Typed `BpttConfig` validation not enforced at training time**
- `BpttConfig.__post_init__` guards (`window >= 1`, `stride >= 1`, `loss_ema_decay` in [0,1)) run only during `HashiModelConfig.from_dict`. `run_epoch` reads the raw dict, so programmatic config mutations after construction bypass validation.
- **Impact:** Low — normal usage always goes through `from_dict` or `from_yaml`.
